- **CRITICAL — every create/delete/archive example in the registry throws before it reaches the wire, and no record says so.** — src/capabilities.ts (91 records), src/resources/base.ts:216, :301, :333 vs :221 — The registry's advertised `examples` for 66 non-update mutating records pass `{ dryRun: true, expectedUpdatedAt: 'example' }` (methods: delete ×26, create ×25, archive ×4, unarchive ×4, deleteAll, deleteById, duplicate, kickoff, upload, createFromTemplate, moveLayout ×1 each). `createOne` calls `this.assertNoExpectedUpdatedAt('createOne', opts)` at base.ts:216 — **before** the `if (opts?.dryRun)` branch at :221 — and `deleteOne`/`setArchived` do the same at :301/:333. That guard throws `HuduConfigError` ("expectedUpdatedAt is not supported on create/delete/archive — it guards update only"); its own comment states "No request is issued either way", so **every one of those 66 examples throws, in dry-run as well as for real**. `updateOne` (:273) is the only primitive that accepts it. Measured: **91 of 223 records** put `expectedUpdatedAt` in their example; **0 of 223 records list `CONFIG_ERROR`** in `errors`; 25 of the 91 are `update` and are correct. Why it matters: `examples` is the field the MCP Toolsmith and agent callers copy verbatim, and the whole point of the layer is a contract an agent can trust; a third of the registry documents calls that fail validation before the first HTTP request. Fix: regenerate examples from the real signature (drop `expectedUpdatedAt` from non-update examples — the generator should derive it from `MutationOptions` per primitive), and add `CONFIG_ERROR` to the `errors` of any record that can raise the guard.
